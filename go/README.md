# ThreeDice — Go

The Go implementation. See the [root README](../README.md) for the game rules, odds table and API reference,
which both services share.

## Tech Stack

- Go 1.26
- chi (routing over `net/http`)
- pgx v5 + sqlc (type-safe SQL, no ORM)
- shopspring/decimal (exact decimal money)
- go-playground/validator
- golang-migrate (schema migration)
- log/slog
- testcontainers-go + testify (integration testing)

The binary is self-contained: migrations and the frontend are compiled in with `//go:embed`, so there is nothing
to deploy alongside it.

## Prerequisites

- **Go 1.26+**
- **Docker** (for PostgreSQL, and for Testcontainers during tests)
- **sqlc** — only to regenerate the database layer: `go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest`

## Running

### 1. Start the database

From the repository root:

```bash
docker compose up -d postgres
```

This starts PostgreSQL 16 on port `5432`. The Go service uses the `threedice_go` database, which
`docker/init-db.sh` creates on first initialisation of the volume. On a pre-existing volume, create it by hand:

```bash
docker compose exec postgres psql -U threedice -d threedice -c 'CREATE DATABASE threedice_go OWNER threedice;'
```

### 2. Run the application

```bash
go run ./cmd/server
```

The application starts on `http://localhost:8081`. golang-migrate creates the schema, and a demo player (`id=1`,
balance `1000.00`) is seeded on first startup. The frontend is served at [http://localhost:8081](http://localhost:8081).

### 3. Run the tests

Tests use **testcontainers-go** — they spin up their own PostgreSQL container. You only need Docker running.

```bash
go test ./...
```

29 integration tests mirroring the [Java suite](../spring-boot/README.md) case for case, plus static-asset tests.

## Configuration

Entirely from the environment (12-factor); there is no config file.

| Variable | Default |
|---|---|
| `DATABASE_URL` | `postgres://threedice:threedice@localhost:5432/threedice_go?sslmode=disable` |
| `PORT` | `8081` |
| `INITIAL_BALANCE` | `1000.00` |

## Regenerating the database layer

`internal/db/` is generated by sqlc from `db/queries/*.sql` against the schema in `db/migrations/`. After editing
either:

```bash
sqlc generate
```

The generated code is committed, so a plain `go build` needs no sqlc installed.

## Notes on matching the Java service

A few places needed deliberate work to keep the two APIs identical. They are worth knowing before editing:

- **`money.Amount` exists because shopspring/decimal's own JSON is wrong for this contract.** It quotes the value
  and trims trailing zeros, so a balance of `1040.00` would marshal as `"1040"`. `Amount` renders `StringFixed(2)`
  unquoted. Any money field in a DTO must use it.
- **`apitime.Time` exists because Go's RFC3339Nano trims trailing zeros** where `java.time.Instant` emits
  fractional seconds in groups of three digits — `.100Z` vs `.1Z`. Any timestamp in a DTO must use it.
- **The valid-product rule is not in the `validate` tag chain.** Bean Validation reports every failing constraint
  on a field; go-playground stops at the first. `predictedValue: 300` has to report both the max failure and the
  valid-product failure, so `validation.ValidatePlaceBet` applies that rule separately and merges the results.
- **`parsePlayerID` prefixes its message with a Java method name** (`getPlayer.playerId: ...`). That is the
  property path Spring puts in the detail for a method-level constraint violation, and clients see it.
- **`handler/static.go` does not use `http.FileServer`**, which would 301 `/index.html` to `/` and write a
  plain-text 404 instead of RFC 7807.

Two known differences remain, both deliberate — see the root README.

## Deploying to Coolify

Create a **second** application pointing at this repository, alongside the Spring one:

| Setting | Value |
|---|---|
| Build Pack | `Dockerfile` |
| Base Directory | `/go` |
| Dockerfile Location | `/Dockerfile` |
| Ports Exposes | `8081` |

Coolify sets the build context to the Base Directory, so the Dockerfile here is self-contained.

> **Base Directory must be `/go`, not `/`.** `Dockerfile Location` is resolved relative to it, so
> `Base Directory: /` + `Dockerfile Location: /go/Dockerfile` finds the file but builds it with the repo root as
> context, and the `COPY go.mod go.sum ./` then fails.

Both services share one PostgreSQL instance but own separate databases. Coolify will not create the second one,
so run this once against your existing instance:

```sql
CREATE DATABASE threedice_go OWNER threedice;
```

Then set:

```
DATABASE_URL=postgres://<user>:<password>@<postgres-host>:5432/threedice_go?sslmode=disable
PORT=8081
```
